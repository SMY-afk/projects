# TikTok Shop 订单成交链路字段映射记录

## 1. 记录规则

- 本文档只记录 Seller Center 显示的类型标签、可观察到的分类层级和 ERP 映射结论。
- 不记录完整订单号、客户昵称、商品名称、物流单号、金额、Token 或平台原始响应。
- “已确认”只表示 Seller Center 页面可见该标签；API 字段名和自动同步可行性仍须以订单详情接口真实响应验证。

## 4. 当前未能从订单列表确认的类型

- `organic` 与 `paid_ads`；
- 达人/自营/商城的单订单归属；
- 站外、橱窗、联盟商品页、搜索或推荐的单订单入口；
- Ads / GMV Max 对应的订单级转化标识。

原因：管理订单列表当前只展示状态筛选和特殊订单标签；“GMV 拆解”提供的是汇总分析，不是订单级数据。联盟中心尚未开放到可查询的订单表现页，未执行任何“开通/解锁权益”操作。

## 5. 下一步字段核验清单

1. 对“免费样品”和“买返样品”各调用一次 TikTok Shop 订单详情，保存脱敏 fixture，并确认实际字段名、枚举值和更新时间。
2. 找到至少一笔 Seller Center 明确归为联盟直播、联盟视频、商家直播、商家视频、商品卡的订单；若分析页不能下钻，则由运营提供对应脱敏订单号作为真值样本。
3. 核验订单详情是否直接返回自然/广告来源；若没有，确认联盟订单接口或 Ads/GMV Max 是否提供可精确关联的订单 ID。
4. 只有已验证字段才进入 `TikTokOrderAttributionSignal` 和 `order_attributions`；其余类型先保持 `unknown`。

## 7. 订单详情接口修正与买返样品复测（2026-08-13）

### 接口与授权核对

- TikTok Shop Partner Center 当前文档定义的订单详情接口为 `GET /order/202309/orders`，版本仍为 `202309`。
- 订单 ID 不是路径参数；必须用查询参数 `ids` 传入，支持最多 50 个 ID。`shop_cipher`、签名参数和 `x-tts-access-token` 均为必填。
- 所需权限为 `seller.order.info`。当前店铺连接处于 `authorized` 状态、令牌未过期，且已包含该权限。
- 先前请求使用了 `/order/202309/orders/{order_id}`。平台以 HTTP 403 返回 `40006` 和 `no schema found`；该信息表明请求未命中已注册的 API schema，不能据此推断订单不存在、令牌失效或缺少订单读取权限。

### 已同步买返样品的只读复测

- 从 Seller Center 已确认的一笔 `买返样品`订单，使用金额和时间窗口在 ERP `orders` 中唯一匹配；仅在诊断过程中使用不可逆短指纹，不记录完整订单号或买家信息。
- 使用修正后的详情接口请求成功：HTTP `200`、平台 `code=0`、返回一笔订单，且返回订单 ID 与请求样本一致。
- 详情数据在 `data.orders[]` 返回；已确认存在 `is_sample_order` 字段。
- 本次详情订单对象中未见 `source`、`affiliate`、`creator`、`campaign`、`ad`、`live`、`video`、`channel`、`content` 或 `gmv` 等订单级归因字段。`delivery_type`、`fulfillment_type`、`shipping_type` 仅为履约/配送信息，不能用于成交链路判定。

### 对实现的影响

- 订单详情客户端已改为使用 `GET /order/202309/orders?ids=...&shop_cipher=...`，并将详情响应从 `data.orders[]` 解析为单笔订单；单元测试和一笔脱敏真实订单的连接器烟雾测试均已通过。
- `is_sample_order` 只能作为“样品”候选信号，不能在未确认枚举语义前单独区分 `免费样品` 与 `买返样品`。
- 本次响应不提供自然/广告、达人/自营/商城、视频/直播/站外/搜索等订单级归因字段；这些维度仍需要独立的联盟或 Ads / GMV Max 订单级关联凭证，缺失时必须保留 `unknown`，不得用汇总报表反推。

## 8. 平台字段 -> 内部字段 -> 显示链路 -> 判定强度

本表的分类枚举、特殊订单优先级、`unknown` 策略和冲突处理顺序，以计划书第 2.1–2.4 节为唯一规范；本节只记录字段证据，不另设一套分类规则。

### 8.1 适用范围与强度口径

- 本表仅覆盖已实测的订单详情接口 `GET /order/202309/orders` 的 `data.orders[]` 响应，以及 Seller Center 已人工确认的标签；不以 GMV 汇总报表替代订单级证据。
- 表中的内部字段是已批准计划中的 `TikTokOrderAttributionSignal` 和 `order_attributions` 契约，**当前尚未创建数据库表或写入归因记录**。
- `强`：平台返回与展示类型一一对应的订单级字段或关联 ID；`中`：平台直接返回但语义不足以完成链路判定；`辅助`：仅用于关联、时效或履约，不能决定链路；`不支持`：当前详情响应未返回该类订单级字段，必须显示 `未知/待补充`。

### 8.2 已返回字段

| 平台字段                                                                  | 返回状态 | 内部字段                                                                        | 显示链路                       | 判定强度 | 判定规则                                                                                                                              |
| ------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------- | ------------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `data.orders[].id`                                                        | 已返回   | `orders.platform_order_id`（订单关联键）                                        | 不显示为成交链路               | 辅助     | 只用于将详情、联盟或广告的订单级证据关联到同一 ERP 订单。                                                                             |
| `data.orders[].is_sample_order`                                           | 已返回   | `TikTokOrderAttributionSignal.is_sample_order`、`evidence_json.is_sample_order` | `特殊订单 > 样品标记 > 待确认` | 中       | 仅显示“样品标记”，不得仅凭该布尔值写入 `special_order_type=sample` 或 `purchase_sample_rebate`，也不得覆盖 Seller Center 的细分标签。 |
| `data.orders[].create_time`、`paid_time`、`update_time`                   | 已返回   | `source_updated_at`、`evidence_json` 的允许时间戳                               | 不显示为成交链路               | 辅助     | 只用于证据时效、同步幂等和与外部订单级记录的时间窗口校验。                                                                            |
| `data.orders[].line_items[].sku_type`                                     | 已返回   | 不映射至归因字段                                                                | 不显示为成交链路               | 辅助     | 商品/SKU 属性不是成交入口或流量来源，禁止据此推导橱窗、联盟商品页或搜索。                                                             |
| `delivery_type`、`fulfillment_type`、`shipping_type`、`delivery_option_*` | 已返回   | 不映射至归因字段                                                                | 不显示为成交链路               | 辅助     | 仅用于履约/配送展示；禁止用于自然、广告、达人、自营、商城、视频或直播判定。                                                           |

### 8.4 Seller Center 标签的边界

| Seller Center 标签 | 自动同步字段                                             | 内部字段/显示                                                                       | 判定强度       | 使用边界                                                                                |
| ------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------------- |
| `免费样品`         | 当前订单详情接口未返回对应细分类字段，**不支持自动同步** | 不自动写入；人工核验时可作为 `special_order_type=sample` 的验证样本                 | 强（人工核验） | 只能用于字段验收和人工复核，不能由同步任务批量推断。                                    |
| `买返样品`         | 当前订单详情接口未返回对应细分类字段，**不支持自动同步** | 不自动写入；人工核验时可作为 `special_order_type=purchase_sample_rebate` 的验证样本 | 强（人工核验） | 需要平台返回明确细分类字段，或后续获得可按订单 ID 关联的样品/联盟接口后，才能自动落库。 |

**页面兜底规则：** 若任一层缺少强证据，链路主展示必须是 `未知`；可在辅助标签显示“样品标记（待确认）”，但不得显示“自然流”“广告”“GMV Max”“达人”“自营”“商城”“视频”“直播”“站外”“橱窗”“联盟商品页”或“搜索推荐”。

## 9. 同一订单复查与历史可回查范围

### 9.1 同一订单来源字段是否会变化

- 对同一笔已同步且 Seller Center 标记为 `买返样品` 的订单，连续两次只读调用修正后的详情接口；请求仅输出订单 ID 短指纹、允许字段路径和哈希后的字段摘要。
- 两次响应的 `update_time` 相同（`1786418967`）、`is_sample_order` 相同（`false`）、来源相关字段路径集合相同、允许字段摘要哈希相同（`bf4e30b2c1cd021b`）。
- 这证明本次复查期间该订单的返回字段没有变化；**不能**证明平台在订单生命周期更新后永远不会改变来源字段，因为没有对同一订单制造或观察到 `update_time` 变化。
- 因此同步策略必须以 `update_time` 变化触发重新取详情并重新评估证据；来源字段如发生变化，应保留新的 `source_updated_at` 与证据哈希，不能覆盖历史审计记录。当前订单详情仍未返回自然/广告或达人/内容入口字段。

### 9.2 历史订单详情可回查时间范围

- 官方 `Get Order Detail` 文档只规定按订单 ID 查询（`ids` 最多 50 个），说明返回订单详情和 `update_time`；未声明“创建后 N 天”或“仅保留 N 个月”的详情回查保证。
- 因此目前不能对外承诺固定的 90/365 天等平台保留期；对任意历史订单，只有实际调用成功才算“可回查”。订单列表接口的时间筛选窗口也不能推导详情接口的保留期限。
- ERP 当前本地已同步订单的可回查范围由自身数据决定：现有店铺订单中最早 `placed_at` 为 `2025-12-31 20:06:49 UTC`，最晚为 `2026-08-13 01:49:31 UTC`，共 992 笔。这个是 ERP 已保存范围，不是 TikTok 平台承诺。
- 本次对最早订单（2025-12-31）、跨季度订单（2026-04-18）和最近订单（2026-08-13）各做了一次脱敏详情回查，三笔均 HTTP 200、返回 1 条订单，且均返回 `update_time`。这只能证明该店铺当前至少可回查到 2025-12-31 的样本，不能把该日期当成平台保留期限下限或上限。
- 后续验收仍需在更早订单可用时继续向前取样；若平台返回订单不存在或超期错误，应记录为“不可回查”，不能以 ERP 本地订单存在替代平台详情可用性。
