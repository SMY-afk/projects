# 后端接口确认清单

在模块开发开始前，前后端负责人共同确认并在 PR 中勾选以下契约。未确认项不得用页面猜测值替代。

## 错误码

- [ ] 统一响应包装：`code` 类型、成功值（当前客户端接受 `0/200/'0'/'200'/'SUCCESS'`）、`message` 和 `data`。
- [ ] HTTP 状态与业务错误的对应关系（400/401/403/404/409/422/429/5xx）。
- [ ] 字段校验错误是否返回字段路径；敏感操作是否使用通用错误文案。
- [ ] 分页、上传、下载和验证码错误是否遵循同一包装。

## 分页

- [ ] 请求参数：`page` 是从 0 还是 1 开始，`pageSize` 上限，排序字段/方向和筛选参数命名。
- [ ] 响应字段：当前商品试点采用 `{ items, total, page, pageSize }`。
- [ ] 空列表、超出页码、删除当前页最后一条后的行为。

## 金额与时区

- [ ] 金额传输禁止浮点数：确认使用最小货币单位整数（推荐）或十进制定数字符串，并明确币种字段。
- [ ] 时间传输统一 ISO 8601，带时区/UTC（推荐 `2026-08-10T10:20:00Z`）；前端展示时注明业务时区。
- [ ] 日期筛选的闭区间/开区间、夏令时和服务端默认时区。

## 权限返回格式

- [ ] 当前用户接口返回角色、权限码的结构和是否包含资源范围/数据权限。
- [ ] 权限码命名与前端 `<module>:<action>` 约定一致；无权限统一 403。
- [ ] 菜单权限与按钮操作权限是否分离，权限变更后的缓存失效策略。

## 文件上传/下载

- [ ] 上传：`multipart/form-data` 字段名、大小/类型限制、分片/进度和病毒扫描状态。
- [ ] 下载：鉴权方式、`Content-Disposition` 文件名编码、`Content-Type`、断点续传和审计要求。
- [ ] 大文件是否使用短时签名 URL；错误响应是否仍为统一 JSON。

## 字典与枚举

- [ ] 字典 endpoint、租户/语言参数、缓存 TTL 和失效机制。
- [ ] 枚举 code 是否稳定、label 是否由后端/前端本地化、未知 code 的降级显示。
- [ ] 字典变更是否需要版本号或生效时间。
