# TikTok Shop 数据指标字典

> 核验日期：2026-08-14  
> 适用范围：`Akeleo Fun Toys`（US）首期只读 Analytics 数据板块  
> 展示原则：只有“支持”状态的指标才能展示真实数值；“待确认”和“不支持”均展示为不可用，不能以 Mock、0 或空值伪装成真实数据。

## 1. 状态定义

| 状态          | 含义                                                    | UI 行为                                |
| ------------- | ------------------------------------------------------- | -------------------------------------- |
| `supported`   | 官方字段、业务口径和测试店铺真实响应均已核验            | 展示数值、币种、统计范围和数据更新时间 |
| `unsupported` | 当前首期 API 没有可安全使用的字段，或字段无法支撑该口径 | 显示“当前不支持”，不计算替代指标       |
| `pending`     | API 或字段存在，但口径、响应样本或适用边界尚未核验      | 显示“待确认，暂不可用”，不展示数值     |

当前店铺已具备 Analytics OAuth scope，但尚未完成真实 API 探针。因此本字典中所有会在 UI 展示数值的指标，当前均不得进入 `supported`。

## 2. 统一时间口径

传输字段的具体类型、精度和 JSON 示例见[数据板块 v1 时间、金额与比例契约](./data-api-contract.md)。

| 项目           | 口径                                                                                                             | 状态        |
| -------------- | ---------------------------------------------------------------------------------------------------------------- | ----------- |
| 统计自然日     | 使用店铺注册时区的日历日，不使用浏览器时区，也不按 UTC 日切分                                                    | `supported` |
| 查询范围       | `start_date_ge` 为包含起始日，`end_date_lt` 为不包含结束日；例如 8 月 1 日至 7 日传 `2026-08-01` 至 `2026-08-08` | `supported` |
| 内部存储       | 保存 `shopTimezone`、`statDate` 和对应 UTC 时间范围；接口响应中的时间戳统一保存为 UTC ISO 8601                   | `supported` |
| 当日数据       | 仅在官方接口明确支持 `today=true` 时标注“当日实时口径”；不与已结算的历史日数据做同口径同比                       | `pending`   |
| 历史数据新鲜度 | 必须以响应中的可用日期或实际 `fetchedAt` 标识；不得假定固定 T+N 延迟                                             | `pending`   |

TikTok Shop Analytics 的日期参数明确按店铺注册时区解释，并使用上述左闭右开范围。[Get Shop LIVE Performance List](https://partner.tiktokshop.com/docv2/page/get-shop-live-performance-list-202509)

## 3. 观看与互动口径

| 指标                            | 对外名称     | 当前口径                                                                                | 状态          | UI 行为    |
| ------------------------------- | ------------ | --------------------------------------------------------------------------------------- | ------------- | ---------- |
| `videoViews`                    | 视频播放次数 | 官方新版本列举 `views` 字段，但当前测试店铺尚未完成响应字段核验；不能将其称为“观看人数” | `pending`     | 不可用     |
| `liveViewers`                   | 直播观看人数 | 官方文档说明为观看直播的 viewers，但没有在当前接入范围内确认其是否跨会话/跨时段去重     | `pending`     | 不可用     |
| `uniqueViewers`                 | 去重观看人数 | 没有已核验的可用字段和去重范围（单场、单日或查询窗口）                                  | `unsupported` | 当前不支持 |
| `playCount`                     | 播放次数     | 不能由 `viewers` 推导；仅在真实响应中存在且官方字段说明确认后才启用                     | `pending`     | 不可用     |
| `likes` / `comments` / `shares` | 互动次数     | 等待实际响应验证字段名、是否去重以及统计窗口                                            | `pending`     | 不可用     |

**禁止映射：** 不得用 `views` 代替去重观看人数，不得用 `viewers` 代替播放次数，也不得用视频和直播两个不同粒度的字段相加。

## 4. 交易、归因与退款口径

| 指标                    | 对外名称   | 当前口径                                                                                                                     | 状态          | UI 行为                              |
| ----------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------- | ------------------------------------ |
| `attributedGmv`         | 归因 GMV   | TikTok 于 2026 年调整部分 Analytics 指标的归因模型；当前文档未给出可稳定配置的归因窗口长度。必须保留 endpoint 版本与字段原名 | `pending`     | 不可用                               |
| `attributedOrders`      | 归因订单数 | 与 GMV 使用同一来源、同一版本，不能从订单表自行反推后冒充平台归因数据                                                        | `pending`     | 不可用                               |
| `grossMerchandiseValue` | GMV        | 仅可展示平台响应的原始 GMV 字段；是否含税、运费、折扣必须随 endpoint 版本和字段说明记录                                      | `pending`     | 不可用                               |
| `refundAmount`          | 退款金额   | 产品性能新版本列出退款字段，但首期尚未接入并核验；不得从订单状态猜算                                                         | `pending`     | 不可用                               |
| `netGmv`                | 净 GMV     | 当前没有经验证的“GMV 减退款”同口径字段或归因规则                                                                             | `unsupported` | 当前不支持；禁止以 `GMV - 退款` 计算 |

归因字段正处于平台统一模型调整期间，字段名保持不变不代表口径不变；接入时必须记录响应 API 版本和文档版本。[Analytics Open API Metric Consistency Adjustment](https://partner.tiktokshop.com/docv2/page/joyljtav)

## 5. 币种与金额

| 项目     | 口径                                                                                                          | 状态          |
| -------- | ------------------------------------------------------------------------------------------------------------- | ------------- |
| 请求币种 | 仅使用官方允许的 `LOCAL` 或 `USD`；未指定时按接口默认 `LOCAL`，不得在前端臆测                                 | `supported`   |
| 金额字段 | 保留官方 `amount` 原始十进制字符串及其 `currency`；内部转换为 `amountMinor + currency` 时必须以十进制运算完成 | `supported`   |
| 汇率换算 | 不做跨币种合并、换算或同比；除非后续引入独立、可审计的汇率数据源                                              | `unsupported` |
| 币种展示 | 每个金额紧邻展示其响应币种；同一图表只允许单一币种，否则拆分或显示不可用                                      | `supported`   |

Analytics 接口支持 `USD` 与 `LOCAL`，默认 `LOCAL`；官方响应使用金额对象携带 `amount` 和 `currency`。[Get Shop LIVE Performance List](https://partner.tiktokshop.com/docv2/page/get-shop-live-performance-list-202509)

## 6. 发布前升级规则

一项 `pending` 指标转为 `supported` 前，必须同时完成：

1. 保存官方文档链接、API 版本、字段路径和字段说明。
2. 使用当前测试店铺执行最小只读探针，并记录脱敏后的字段名、分页、店铺时区和可用日期。
3. 确认该字段的去重范围、归因范围、退款处理和币种语义；若官方未定义，保持 `pending`。
4. 为后端字段映射与前端“不可用”状态分别补充自动化测试。
5. 仅在真实数据成功读取后解除对应 UI 指标的不可用状态；API 失败不得回退为 Mock。
